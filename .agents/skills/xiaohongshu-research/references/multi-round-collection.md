# 多轮采集说明

## 为什么需要多轮

小红书搜索结果会随查询词、排序、时间和个性化推荐变化

单轮结果只能代表一个可见切片

多轮采集使用不同查询和排序获得多个切片，再用稳定笔记 ID 合并

每次运行执行三至五轮

所有轮次和详情在一个页面中串行完成，相邻自动动作至少间隔三秒

同一次运行已经读取的查询、笔记和评论保留十五分钟，重复请求复用已有观察

登录、扫码、滑块、验证码、限流和宿主策略阻止出现后不自动重试

## 每轮记录什么

| 字段 | 解释 |
| --- | --- |
| `round_id` | 本轮编号 |
| `query` | 本轮实际查询词 |
| `sort_mode` | 综合、最新、最多点赞、最多收藏或最多评论 |
| `retrieved_at` | 本轮完成读取的带时区时间 |
| `result_count` | 本轮读取的卡片数量 |

每张卡片还要记录笔记 ID、名次、标题、作者、可见时间、热度、封面和直接链接

搜索页面链接可能带有临时查询参数

保存时只保留笔记 ID 并生成 `https://www.xiaohongshu.com/explore/<note-id>` 形式的规范链接

## 怎样判断结果趋于稳定

脚本按轮次计算第一次出现的唯一笔记数量

至少执行三轮后，如果连续两轮的新增唯一笔记都不超过计划阈值，可以标记为 `saturated`

这只表示当前计划继续搜索的新增收益很低，不表示平台没有其他内容

## 怎样选详情笔记

优先保留跨轮重复出现、覆盖不同查询、热度可见且链接有效的笔记

选样还要保留不同时间与不同观点，不能只选热度最高的同一种结论

脚本先做稳定去重和基础排序，Agent 在详情读取时仍要核验内容是否真的覆盖研究问题

## 明确不使用的方法

- 不导出 Cookie 或复制浏览器资料
- 不创建隐藏的第二登录会话
- 不使用代理轮换或设备指纹伪装
- 不自动解决验证码
- 不通过高并发提高覆盖
