# 采集后端路由

## 这份文件解决什么问题

本 Skill 需要从小红书搜索页、笔记页和公开评论读取当前信息

采集能力可以来自成熟工具，也可以来自 Codex 支持的浏览器

本页规定先用哪一种、什么情况下切换、哪些能力永远不能调用

## 固定选择顺序

| 顺序 | 后端 | 什么时候使用 | 允许做什么 |
|---|---|---|---|
| 1 | OpenCLI | 用户已经安装、信任并连接其浏览器扩展 | 搜索笔记、读取笔记、读取公开评论 |
| 2 | 受支持 Chrome | OpenCLI 未安装、未连接、版本不兼容或用户未信任 | 操作当前已登录页面并读取公开搜索、笔记与评论 |

后端不可用只表示换用下一条受支持路径

登录、验证码、宿主安全策略和权限不足不是后端切换理由，命中这些情况必须停止并报告真实状态

## 为什么优先支持 OpenCLI

OpenCLI 已经实现小红书搜索、笔记和评论适配器，并输出结构化数据

它使用当前浏览器会话，可减少重复编写页面字段提取代码

它采用 Apache-2.0 许可证，并包含适配器测试

本 Skill 仍负责查询计划、多轮覆盖、稳定 ID 去重、代表性选样、证据分级和最终综合

## OpenCLI 使用条件

以下条件全部满足时才能选择 OpenCLI

- 用户已经自行安装并信任当前 OpenCLI 版本
- 浏览器扩展已经连接，且当前会话由用户本人登录
- 当前版本可以执行小红书搜索、笔记和评论读取动作
- 调用范围能够限制为只读动作
- 返回结果可以转换为本 Skill 的输出 Schema
- 保存前可以移除 `xsec_token` 和其他临时查询参数

本仓库不自动安装 OpenCLI，不捆绑其扩展，不复制其代码，也不替用户授予浏览器权限

## OpenCLI 动作白名单

| 动作 | 用途 |
|---|---|
| `xiaohongshu.search` | 按查询和受支持筛选读取笔记卡片 |
| `xiaohongshu.note` | 按笔记 ID 读取正文、图片和公开指标 |
| `xiaohongshu.comments` | 按笔记 ID 读取公开评论 |

白名单以外的动作一律不调用

发布、编辑、删除、点赞、收藏、关注、评论、私信、举报和 Cookie 读取都属于禁止动作

## 受支持 Chrome 路径

受支持 Chrome 路径使用 Codex 已提供的 Chrome 控制能力

它复用当前已登录标签页，通过页面可访问结构或 DOM 读取公开内容

它必须遵守与 OpenCLI 相同的查询轮次、限速、字段、Schema、验证码停机和只读边界

## 输出怎样保持一致

无论使用哪一种后端，每轮搜索都必须返回相同的 `rounds` 和 `candidates` 结构

笔记核验也必须返回相同的 `inspection` 结构

后端不能自行宣布共识、跳过来源追溯或改变置信度规则

后端返回缺少字段、类型错误、临时令牌或无法确定来源时，validator 会拒绝结果

## 第三方项目采用标准

引入新的第三方后端前必须记录以下信息

- 仓库地址、许可证和当前维护状态
- 能否只启用所需的读取动作
- 浏览器、Cookie、文件和网络权限
- 是否存在测试及测试覆盖的真实能力
- 输出字段能否稳定映射到本 Skill Schema
- 依赖安全扫描结果和已知漏洞
- 停止维护或接口变化后的回退路径

没有明确许可证的项目只能学习公开思路，不能复制代码进入本仓库

权限范围明显大于任务需要的工具不能自动安装

## 已审计项目

| 项目 | 结论 | 原因 |
|---|---|---|
| `jackwener/OpenCLI` | 作为可选首选后端 | 许可证明确、已有结构化适配器和测试；扩展权限较高，必须由用户自行信任和安装 |
| `lucasygu/redbook` | 不作为默认后端 | 许可证明确且功能较全；会提取浏览器 Cookie 并包含写操作，超出本 Skill 的凭据边界 |
| `xpzouying/xiaohongshu-mcp` | 只学习接口设计 | 项目成熟度较高；没有明确许可证并包含广泛账户写入能力 |
| `Panniantong/Agent-Reach` | 学习多后端路由 | 路由和健康检查成熟；小红书数据仍依赖其他后端 |

审计结论需要在依赖升级或准备默认启用第三方后端前重新检查
